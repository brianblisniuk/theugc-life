## Question

Once a creator's historical import has a fixed end, how do new messages the creator wrote, and replies on those threads, arrive without a second full import, without Pub/Sub, and without a new Google scope?

## Locked behavior

- Poll `history.list` (`historyTypes=messageAdded`) about every 15 minutes, and on creator login. The 15 minutes is a database due time. Discharge is `npm run gmail:sync:work`, the same operator-worker mechanism B03 established, plus the login trigger. No production cron and no app-layout sync.
- The forward window starts at the greatest `window_end_at` of completed historical imports for that mailbox. An active historical import refuses sync. No completed import means no sync.
- Inclusion is D068. Inbound-only threads are not stored. Drafts are not stored. A `SENT` message that is outside both the historical window and the forward window, and was never stored, does not make the thread a candidate.
- One `historyId` per mailbox. HTTP 404 from `history.list` clears it and that run falls back to a bounded re-scan: `SENT` search in the forward window, plus `threads.get` of already-stored non-draft `SENT` threads, then `users.getProfile` for a new `historyId`. `threads.get` 404 stays "thread gone".
- Idempotent on the B03 message primary key. One active run per mailbox. Lease compare-and-swap.
- After acquisition, the existing local pipeline runs: normalize, outreach (B06's existing eligibility gate), reply chronology, commercial meaning. D072 is not modified.
- B06's per-thread horizon advances only for threads that completed sync fetched.
- Disconnect and deletion cancel sync and purge on the existing deletion path. No sync after revoke. Reconnect starts a new run and keeps a surviving `historyId`. A reauth or consent pause becomes runnable again when the mailbox is connected.
- Gmail-side `messagesDeleted` and label-only changes are not applied to stored rows.
- No new scope, no `gmail.send`, no Pub/Sub, no model call, no new provider of private data.
- Pilot KPIs on the tracker row are not in D076 and are not built here.
